> **Para todo agente (humano o IA) que trabaje en este repo.** Este documento es el contrato:
> define las reglas inquebrantables, qué hay dentro de `research/`, qué código reutilizar de cada
> notebook, y el playbook para entrenar, validar (backtest) y operar el modelo de volatilidad
> multi-activo (crypto, acciones, oro/metales, opciones).
>

## 1. Misión del proyecto

Construir un **sistema cuantitativo profesional de volatilidad** que:

1. **Prediga** volatilidad futura (h=4/8/12/24h) y probabilidad de expansión de vol, con
   calibración honesta (ECE<0.03) y skill medible vs HAR-RV.
2. **Opere** la prima de volatilidad / expansiones de vol en varios mercados:
   **crypto** (BTC/ETH/top-50, opciones Deribit), **acciones** (SPX/SPY/acciones), **oro y metales**
   (GLD, XAU, GC=F, SLV, SI=F) y **opciones** (Deribit crypto, CBOE equities).
3. **Compare la rentabilidad por activo** con métricas válidas (Sharpe neto + DSR + PSR + maxDD)
   y asigne capital al mejor conjunto (Kelly fraccional, nunca full-Kelly).
4. **Valide todo con backtests a prueba de sobreajuste** (walk-forward purgado, embargo,
   CPCV, PBO, DSR, placebo) antes de arriesgar un dólar, y pase a paper → live gradualmente.

El núcleo ya existe en la raíz del repo (Volatility Lab, loop estilo Karpathy) y hoy opera solo
crypto H1. `research/` contiene la base de conocimiento y el código para extenderlo a multi-activo.

## 2. Reglas inquebrantables

### 2.1 Causalidad (la regla #1 — violarla invalida TODO)

- **Toda feature, umbral, normalización o estadístico debe usar solo información disponible en el
  instante t.** Prohibido: `shift(-k)` (fuera de la construcción de targets), `.mean()`/`.std()`
  globales sobre toda la serie, fits de modelo sobre el dataset completo, percentiles full-sample.
- `prepare.py check_causal` recalcula features con el futuro truncado: **si cambian, aborta.**
- Los targets SON la única excepción: `make_targets` usa el futuro por definición, nunca como input.
- GARCH/ML/escaladores: **refit walk-forward** sobre ventana expandida (ver §5.3), no fit único.

### 2.3 Método de investigación (loop)

1. **Una idea = UN cambio pequeño y aislado** en `strategy.py` → `python loop.py run "qué y por qué"`.
   El loop decide keep/revert. Leer `results.tsv` para no repetir ideas.
2. **Presupuesto**: cada corrida tiene `TIME_BUDGET`. Si la idea lo excede, simplificarla.
3. **Métrica del loop**: `score = vol_skill_vs_HAR + BSS_expansion_vol` (no optimizar nada más).
4. **~50 trials sobre los mismos datos ≈ límite de sobreajuste**: el DSR lo penaliza.
   Frenar y pasar al vault (`loop.py final`, UNA sola vez).
5. **Simplicidad gana**: a igualdad de score, menos código/parámetros.
6. **Criterio de parada**: 10 trials sin mejora → vault → reportar gates.

### 2.4 Validación (ningún número se cree sin esto)

- **Ninguna decisión sobre métricas in-sample.** Solo out-of-sample purgado + embargo (24h en H1).
- **DSR obligatorio** con el nº de trials del ledger (y `expected_max_sr` de `research/Untitled16`).
- **PBO (CSCV)** bajo y folds CPCV estables antes de creer en un Sharpe alto (§5.6).
- **Placebo**: correr la señal desplazada (`shift_null`) — si "funciona" igual, la lógica es falsa.
- **Costos realistas por mercado** (§6.3): crypto 10bps/lado (default), equities 2–5bps + spread,
  opciones comisión por contrato + spread en prima (0.8% ida y vuelta en el notebook de referencia).
- **Sin look-ahead en el tuning**: la búsqueda SL/TP/hold de `pricce_volatility_test` es un ejemplo
  de qué NO hacer en producción (grid sobre todo el histórico) — replicar la idea con walk-forward.

### 2.5 Seguridad y operativa

- `live.py` es **PAPER**. `execute()` es el único punto donde se conecta un broker real. Nunca
  conectar dinero real sin: gates pasados en vault + 4+ semanas de paper + kill-switch probado.
- **Kill-switch con pocas muestras es ruidoso** — no ajustarlo con <200 señales.
- Shorts requieren futuros/margen (crypto: perps KuCoin/Deribit; equities: IB/Alpaca margin).
- Sesgo de supervivencia: el top-50 actual de KuCoin no es el top-50 de hace 2 años.
- **Licencias**: TimesFM-3 (`PARAMS["timesfm"]=True`) es NO comercial, GPU, no probado. Tardis
  (en `Untitled15`) requiere API key de pago. Respetar rate limits de Deribit/CBOE/Yahoo.
- **Riesgo por trade**: 1% por defecto (`RIESGO_POR_TRADE=0.01`), multiplicado por el régimen
  (`risk_multiplier` de Cornish-Fisher, §5.5). Kelly fraccional ≤ 0.5·f*.
- No ejecutar celdas completas de notebooks de `research/` (algunos pesan 50MB o descargan GBs);
  extraer funciones a módulos limpios bajo `src/` citando el notebook de origen (§7).

### 2.6 Convenciones de código

- Python 3.11+, pandas/numpy idiomático; features como columnas con MultiIndex `(sym, ts)`.
- Todo lo que importa el futuro debe fallar en `check_causal`, no pasar en silencio.
- Módulos extraídos de `research/` → `src/` con docstring que cite el notebook origen.
- `float32` para features (como hace `strategy.py`); timestamps UTC ISO.
- **Agrupar series de tiempo SIEMPRE con `df.groupby("ts")`** (nunca `np.unique(tts,
  return_index=True)`): el panel está ordenado por `(sym, ts)`, así que `np.unique` devuelve
  "días" que en realidad son trozos de UN solo símbolo y rompe cualquier backtest
  cross-seccional silenciosamente (ver §10, lección 1).
- Todo modelo de clasificación debe exponer **probabilidad** (`predict_proba(...)[:, 1]`),
  nunca etiquetas 0/1: las etiquetas destruyen BSS/Sharpe y no se notan hasta el final.

### 5.1 HAR-RV walk-forward (de `Untitled15.ipynb`, `har_rv_forecast`)

Regresión HAR sobre varianzas realizadas (diaria, semanal 5, mensual 22) para predecir la media de
varianza de los próximos `h` días. **Refit cada 21 días sobre ventana expandida**, con floor
exponencial (EWMA α=0.06) como mínimo. Es EL baseline contra el que `prepare.py` mide el skill:

```python
def har_rv_forecast(ret, h, bpy, refit=21, min_train=250):
    r2 = pd.Series(np.nan_to_num(ret) ** 2)
    n = len(r2)
    d, w, m = r2, r2.rolling(5).mean(), r2.rolling(22).mean()
    y = r2.rolling(h).mean().shift(-h)          # target: SOLO aquí se usa futuro
    X = np.column_stack([np.ones(n), d.values, w.values, m.values])
    ew = r2.ewm(alpha=0.06, adjust=False).mean().values
    fc = ew.copy()
    for t in range(min_train + 22, n, refit):
        umax = t - h
        rows = np.arange(22, umax + 1)
        rows = rows[np.isfinite(y.values[rows])]
        if len(rows) < min_train:
            continue
        beta, *_ = np.linalg.lstsq(X[rows], y.values[rows], rcond=None)
        blk = np.arange(t, min(t + refit, n))
        fc[blk] = np.maximum(X[blk] @ beta, 0.25 * ew[blk])
    return np.sqrt(np.maximum(fc, 1e-10) * bpy)
```

### 5.2 GARCH(1,1) — dos niveles (de `arch_garch.ipynb` y `pricce_volatility_final_dasboard_cloud`)

Manual (didáctico, anualizada): `var[t] = omega + alpha*r[t-1]**2 + beta*var[t-1]`, `var *= 252`.
Producción (walk-forward con `arch`): refit cada `refit_every=500` barras sobre ventana expandida,
forecast multi-paso mantenido hasta el próximo refit, **fallback a rolling-std(30) si falla**:
`calc_garch_vol_walkforward(returns, tf_seconds, refit_every=500, min_train=300)`.

### 5.3 IV proxy y umbral walk-forward (de `pricce_volatility_final_dasboard_cloud`)

- **IV proxy sin opciones**: percentil rolling(60) de la RV + sesgo + EWM(20), floor 1.05·RV.
  Útil cuando el activo no tiene mercado de opciones (metales spot, alts).
- **Umbral de señal walk-forward** (`walk_threshold`): regresión lineal rolling IV→RV futura
  (train=100, fwd=20, step=20), punto fijo `th = intercept / (1 - coef)`, ffill/bfill.
  **Este es el patrón correcto de calibrar un umbral sin look-ahead.**

### 5.4 Validación estadística (de `Untitled16.ipynb` — copiar a `src/validation.py`)

- `sharpe(r, ppy)`, `sortino(r, ppy)` — con `ppy=365*24` para H1 crypto, `252` para equities.
- `psr(sr_obs, sr_bench, n, skew, kurt)` — Probabilistic Sharpe Ratio (ajusta por skew/kurt).
- `expected_max_sr(n_trials, sr_var)` — Sharpe máximo esperado por múltiples pruebas (euler).
- `cpcv_splits(n_obs, n_blocks=6, n_test=2, purge=48, embargo=48)` — CPCV purgado.
- `pbo_cscv(returns_matrix, n_trials)` — Probability of Backtest Overfitting (CSCV).
- `validate_strategy(returns, ...)` — dict completo: sharpe/sortino/skew/kurt/psr_vs_0/psr_vs_1/
  **dsr**/cpcv fold sharpes. **Usar este dict como reporte estándar de cualquier backtest.**

### 5.5 Régimen de riesgo Cornish-Fisher (de `pricce_volatility_final_dasboard_cloud`)

`rolling_cornish_fisher_regime(returns, window)`: skew/kurtosis rolling → mVaR 95 → régimen
(`gaussian`/`moderate`/`heavy_tails`/`negative_skew`) → `risk_multiplier`
(1.0 / 0.85 / 0.65 / 0.60). **Todo rolling (causal)**. Usarlo para escalar el sizing por trade.

### 5.6 ML con folds purgados (de `pricce_volatility_final_dasboard_cloud`)

`purged_walkforward_folds(n, n_splits, purge, embargo, min_train=300)` + `train_xgboost_purged`:
StandardScaler fit SOLO en train, XGBClassifier (n_est=80, depth=4, lr=0.1, subsample=0.8),
predicciones out-of-fold, AUC OOF reportado, señal si prob>0.6. Label de ejemplo:
`build_xgb_labels`: 1 si IV cae >5% en `hold` barras (colapso de vol = vender prima).

- **MC fair value real-world**: `mc_fair_value_call(S0,K,T,mu,sigma,r,...)` — precio bajo drift
  estimado vs BS risk-neutral = **edge estimado del trade** (idea central de `pricing.ipynb`).
- **Bootstrap estacionario + Newey-West**: `stationary_bootstrap_means`, `nw_t` (`Untitled15`) —
  para t-stats robustos a autocorrelación de PnL.
- **Placebo shift_null**: `shift_null(df, legs, mask, sel_dates, cfg, cost, rng)` (`Untitled15`) —
  evaluar la señal desplazada; si rinde igual, la lógica es falsa.
- **Placebo / fracciones de Kelly**: `how_to_trade_with_the_kelly_criterion.ipynb`.
- **Simulación OU**: `ou_process` (varios notebooks) — mean reversion de log-IV.
- **Greeks BS**: `call_delta/theta/vega/rho` (`Managing Option Portfolios.ipynb`).

### 6.2 Fase 1 — Extensión multi-activo (oro, metales, acciones, opciones)

   - Acciones / ETFs / futuros (SPY, GLD, SLV, GC=F, SI=F): Yahoo (`yfinance`, cortes de 700 días

   - Opciones crypto: **Deribit v2** (clase `Deribit` del Arsenal: cadena, DVOL, ticker, candles).
   - Opciones equities: cliente CBOE + NBBO (`Volatility_Arsenal_CBOE`).
   - Microestructura: liquidaciones (Coinglass/Bykaranteli en el Arsenal), OI/GEX/max-pain
     (`Untitled16.build_oi_panel/build_gex_history/build_max_pain_series`).
2. **Generalizar el panel**: extender el MultiIndex `(sym, ts)` a activos no-crypto. Los horarios
   difieren (equities RTH, futuros casi-24h): manejar sesiones y alinear timestamps UTC; la
   estacionalidad horaria de `strategy.py` (`hr_sin/hr_cos`) debe condicionarse por activo.
3. **Features por activo**: el esquema de `strategy.py` (ret multi-h, RV multi-escala, Parkinson,

4. **Modelo**: mismo contrato `fit(Xtr, ytr, task, h)`. Un modelo global con dummies de activo
   vs un modelo por activo: decidir por PBO, no por intuición (§5.4).

### 6.3 Fase 2 — Comparar rentabilidad por activo (asignación de capital)

Para cada activo/mercado, correr el MISMO backtest walk-forward y producir el reporte estándar
`validate_strategy()` (§5.4). Costos por mercado (bps/lado aproximados, calibrar con datos reales):

| Mercado | Costo ida+vuelta | Notas |
|---|---|---|
| Crypto spot (KuCoin top-50) | 10–20 bps | shorts solo vía futuros/perps |
| Perps crypto | 5–10 bps + funding | funding puede comerse el edge del corto de vol |
| Opciones (Deribit/CBOE) | 0.5–1% de prima + comisión/contrato | spread domina; SL/TP sobre prima (§3.1) |
| Acciones/ETFs | 2–5 bps + spread | GLD/SPY muy líquidos |
| Futuros (GC, SI) | comisión fija + spread de tick | sizing por contratos, no % |

Criterio de selección (en el vault, nunca en dev): **DSR>0.95** y Sharpe neto > `sharpe_lower_bound`
(§5.7). Asignación: **Kelly fraccional (≤0.5·f\*)** ponderado por el `risk_multiplier` del régimen
(§5.5), con cap de vol objetivo de cartera y las reglas de correlación de `wyts.ipynb`
(estrategias independientes > diversificación ingenua). Revisar la tabla mensualmente.

### 6.4 Fase 3 — Entrenamiento final y puesta en producción

1. `python loop.py final` → vault (UNA vez). Guardar artefactos del modelo (joblib) + PARAMS.
2. `python live.py train` → entrena con todo el histórico disponible (sin vault).
3. `python live.py run` → señales horarias, monitor, kill-switch (PAPER obligatorio 4+ semanas).
4. Conectar `execute()` con el broker (KuCoin futures / Deribit / IB) SOLO cuando:
   gates del vault pasados + paper estable + kill-switch probado + costos verificados en vivo.
5. Monitoreo continuo: comparar Sharpe live vs backtest (`sharpe_lower_bound` como suelo); si el
   live cae bajo el suelo durante ~100 trades, apagar (ver `When to Stop Trading...ipynb`).

### 6.5 Backtesting — checklist obligatoria antes de creer en cualquier resultado

- [ ] Walk-forward purgado + embargo (24h H1 crypto; 1–2 días equities).
- [ ] Features causales (check_causal pasa).
- [ ] Costos de mercado aplicados por lado (§6.3).
- [ ] `validate_strategy()` completo: PSR vs 0 y vs 1, **DSR con nº de trials real**, CPCV estable.
- [ ] PBO bajo (re-entrenar el selector en mitades aleatorias IS/OOS, §5.4).
- [ ] Placebo shift_null falla (la señal real SÍ supera al placebo).
- [ ] Sensibilidad: pequeños cambios de parámetros no destruyen el resultado (`robust_verdict`).
- [ ] Bootstrap del PnL (drawdowns esperados, riesgo de ruina, §3.6).
- [ ] Régímenes: el edge no vive solo en un régimen (`Profitable vs Tradable`, `wmtf`).

### 10.4 Lecciones operativas (bugs reales de esta integración)
1. `np.unique(tts, return_index=True)` NO agrupa por fecha en un panel `(sym, ts)` ⇒ usar
   `groupby("ts")`. Rompía el L/S cross-seccional sin dar error.
2. `predict()` devuelve etiquetas 0/1 ⇒ BSS≈−0.9. Siempre `predict_proba(...)[:,1]`.
3. Señales des-demanadas ⇒ umbral `0±CONF_MIN`, no `0.5±CONF_MIN` (mezclar escalas deja el
   libro sistemáticamente corto).
4. Sin dollar-neutralización estricta, la deriva del mercado contamina el placebo.
5. El placebo se juzga en **bruto**; su versión neta es negativa por costos de turnover.
